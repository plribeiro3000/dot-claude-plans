## Resultado da Auditoria: String `"true"` passada para variavel GraphQL Boolean

### Modelo Filter (`/Users/plribeiro3000/Projects/4Shark/app-webclient/src/app/shared/filter.model.ts`)

Campos relevantes e seus tipos no modelo:
- `enabled: string` (linha 71) - tipo string
- `override: boolean` (linha 83) - tipo boolean
- `shared: boolean` (linha 96) - tipo boolean
- `orphan: string` (linha 82) - tipo string (no model), tipado como string
- `primary: string` (linha 90) - tipo string

### Campo `enabled` - TODOS CORRETOS

Todas as 29 ocorrencias de `variables.enabled = params.enabled` utilizam a conversao correta `params.enabled === 'true'`. Nenhuma instancia passa a string diretamente.

### Campo `orphan` - CORRETO

`/Users/plribeiro3000/Projects/4Shark/app-webclient/src/app/user/user.service.ts`, linha 60:
```typescript
variables.orphan = params.orphan === 'true';
```

### Campo `primary` - CORRETO

`/Users/plribeiro3000/Projects/4Shark/app-webclient/src/app/user-identifier/user-identifier.service.ts`, linha 52:
```typescript
variables.primary = params.primary === 'true';
```

### Campo `override` - BUG ENCONTRADO

**Arquivo:** `/Users/plribeiro3000/Projects/4Shark/app-webclient/src/app/plan/plan.service.ts`
**Linha:** 62

```typescript
if (params.override !== undefined && params.override !== null) {
    variables.override = params.override;  // <-- BUG: sem conversao boolean
}
```

A variavel GraphQL espera `$override: Boolean` (linha 99 do mesmo arquivo). Embora `override` esteja tipado como `boolean` no modelo Filter, quando o valor vem dos query params do Angular Router (URL), ele chega como `string`. O componente `plan.component.ts` (linha 86-87) recebe query params e cria `new Filter(params)` diretamente. Se um usuario acessar a pagina com `?override=true` na URL, o valor sera a string `"true"`, nao o boolean `true`.

**Contexto atenuante:** O `selectOverride` no componente (linhas 366-374) converte corretamente para boolean antes de atribuir ao filter. Portanto, o bug so se manifesta quando o valor vem diretamente da URL (deep link / bookmark com query params), nao quando o usuario seleciona no dropdown.

### Campo `shared` - BUG ENCONTRADO

**Arquivo:** `/Users/plribeiro3000/Projects/4Shark/app-webclient/src/app/plan/plan.service.ts`
**Linha:** 74

```typescript
if (params.shared !== undefined && params.shared !== null) {
    variables.shared = params.shared;  // <-- BUG: sem conversao boolean
}
```

A variavel GraphQL espera `$shared: Boolean` (linha 103 do mesmo arquivo). Mesmo cenario do `override`: quando vem via query params da URL, o valor e uma string.

**Contexto atenuante:** Igual ao `override` - o `selectShared` no componente (linhas 355-363) converte corretamente. O bug ocorre apenas em deep links.

### Resumo dos bugs

| Arquivo | Linha | Campo | Tipo GraphQL | Conversao aplicada? |
|---------|-------|-------|-------------|-------------------|
| `plan.service.ts` | 62 | `override` | `Boolean` | NAO |
| `plan.service.ts` | 74 | `shared` | `Boolean` | NAO |

**Total de instancias com bug: 2**, ambas no arquivo `/Users/plribeiro3000/Projects/4Shark/app-webclient/src/app/plan/plan.service.ts`.

A correcao para ambos seria:
```typescript
// Linha 62 - override
variables.override = params.override === true || params.override === 'true';

// Linha 74 - shared  
variables.shared = params.shared === true || params.shared === 'true';
```

Ou, alternativamente, se o tipo do modelo fosse corrigido para `string` (consistente com a realidade dos query params), a conversao padrao `=== 'true'` usada em `enabled` funcionaria.

Nota adicional: o fato de `override` e `shared` estarem tipados como `boolean` no modelo Filter (enquanto `enabled` esta tipado como `string`) cria uma inconsistencia que mascara o problema no TypeScript - o compilador nao alerta porque `boolean` e aceito sem conversao, mas na pratica o Angular Router entrega strings.
