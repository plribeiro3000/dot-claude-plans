## Technical Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| **Pattern to Follow** | Plan Goal Audit implementation | Already proven to work correctly, consistent with team standards |
| **GraphQL Field Order** | Alphabetical order (actions first) | Team convention, improves code consistency and readability |
| **Permission Check Logic** | `status === 'final' && actions?.includes('download')` | Combines status validation with backend permission signal |
| **Optional Chaining** | `actions?.includes()` | Prevents errors if backend doesn't return `actions` field |
| **Frontend-Only Phase** | Separate from backend/infrastructure changes | Allows incremental rollout, easier testing, reduces deployment risk |
| **No Model Changes** | Keep using `any` type for audit objects | Avoid scope creep, focus on permission logic only |

## Risks

| Risk | Impact | Mitigation |

| **Inconsistent template structure** | Low | Each audit may have slightly different HTML, need to locate correct `<a>` tag |
| **Breaking existing functionality** | Low | Only adding conditional, not changing download URL behavior |
| **Missing audit types** | Medium | Verify all 9 audit types exist in codebase before starting |

## Objective

Implement presigned URL generation for secure audit file downloads. Replace direct S3 public URLs with time-limited presigned URLs that validate user permissions before generating.

## Backend Implementation (COMPLETE)

**PR #4629** - Implemented:

1. **GraphQL Mutation**: `getTemporaryAttachment(id: ID!)`
   - Receives attachment ID
   - Validates user permission via policy (using POLICIES hash mapping)
   - Returns `TemporaryAttachmentGraphqlType` with `presigned_url`

2. **Attachment#presigned_url method**:
   - Uses `Aws.connection.get_object_url` (fog-aws)
   - 10-minute expiration (configurable via `SIGNED_URL_EXPIRATION` env var)
   - Returns nil if file path is blank

3. **Security**:
   - Policy validation per audit type (CalendarAuditPolicy, VariableAuditPolicy, etc.)
   - Missing policy mapping raises `KeyError` (500) to catch configuration bugs
   - Cross-account access blocked by policy (checks `company_id`)

## Frontend Integration (PENDING)

**Changes needed in app-webclient:**

1. Replace direct `publicUrl` usage with mutation call on download click
2. Flow:
   - User clicks download button
   - Frontend calls `getTemporaryAttachment` mutation with attachment ID
   - Backend validates permission, returns presigned URL
   - Frontend redirects to presigned URL (download starts)

3. Benefits:
   - URL generated on-demand (never expires before use)
   - Permission validated at download time (not at page load)
   - User never sees the presigned URL (immediate redirect)

download(event: Event, document: any) {
  event.preventDefault();
  const attachmentId = document.attachment?.id;
  if (!attachmentId) return;

  const query = `mutation { getTemporaryAttachment(id: ${attachmentId}) { presignedUrl } }`;
  this.getTemporaryAttachmentService.mutation('getTemporaryAttachment', query).subscribe(
    (response: any) => {
      const url = response.data?.getTemporaryAttachment?.presignedUrl;
      if (url) window.location.href = url;
    },
    (err: any) => {
      this.showMessage(err.errors?.[0]?.message || this.translateService.instant('errors.download_failed'));
    },
  );
}

# Phase 12 - Remove public-read ACL from Uploads (COMPLETE)

## Objective

Remove `X-Amz-Acl: public-read` header from presigned upload URLs, making new uploads private by default.

## Prerequisites

- ✅ Phase 11 complete (backend cleanup deployed)
- ✅ All downloads use presigned URLs

## Background

### Current Flow
```
Frontend requests upload URL → Backend generates presigned PUT URL with X-Amz-Acl: public-read
                            → Frontend uploads to S3
                            → File saved with public-read ACL (anyone can access)
```

### New Flow
```
Frontend requests upload URL → Backend generates presigned PUT URL (no ACL header)
                            → Frontend uploads to S3
                            → File saved with private ACL (only presigned URL access)
```

## Issue Encountered - 403 Forbidden (2025-12-30)

**Problem:** After deploying backend changes (app #4669), uploads started failing with 403 Forbidden.

**Root Cause:** S3 presigned URLs sign specific headers. When backend stopped signing `X-Amz-Acl`, but frontend still sent it, S3 rejected the request because of header mismatch.

```
Backend signs:    Content-Type, X-Amz-Expires, X-Amz-Date
Frontend sends:   Content-Type, X-Amz-Expires, X-Amz-Date, X-Amz-Acl (NOT SIGNED!)
S3 response:      403 Forbidden (unsigned header present)
```

**Solution:** Frontend must also stop sending `X-Amz-Acl` header. This requires **synchronized deployment**.

# Phase 14 - Clean Existing Object ACLs (PENDING)

## Objective

Remove `public-read` ACL from all existing S3 objects for defense in depth.

## Prerequisites

- Phase 13 complete (Block Public Access active)
- System stable with private-only access

## Background

### Why This Phase?

Even with Block Public Access enabled, objects retain their individual ACLs. If Block Public Access is accidentally disabled, all objects with `public-read` would become public again.

**Defense in depth:** Remove object-level ACLs so even if the bucket block is removed, files stay private.

## Implementation

### Script to Clean ACLs

```bash
#!/bin/bash
# clean_s3_acls.sh

BUCKET="your-bucket-name"
PREFIX="uploads/"

echo "Listing objects in s3://$BUCKET/$PREFIX"

aws s3api list-objects-v2 \
  --bucket "$BUCKET" \
  --prefix "$PREFIX" \
  --query 'Contents[].Key' \
  --output text | \
tr '\t' '\n' | \
while read key; do
  echo "Setting private ACL for: $key"
  aws s3api put-object-acl \
    --bucket "$BUCKET" \
    --key "$key" \
    --acl private
done

echo "Done!"
```

### Considerations

- **Large buckets:** May need to paginate or run in batches
- **Cost:** S3 API calls have cost (minimal for PUT-acl)
- **Time:** Depends on number of objects
- **No downtime:** Safe to run while system is live

3. Run full migration
4. Verify with spot-checks

  def self.policy(policy = nil)
    @policy ||= policy
  end

  argument :id, ID, required: true
  type TemporaryFileGraphqlType, null: true

  def resolve(id:)
    raise NotImplementedError, "#{self.class.name} must declare `model`" unless self.class.model
    raise NotImplementedError, "#{self.class.name} must declare `scope`" unless self.class.scope
    raise NotImplementedError, "#{self.class.name} must declare `policy`" unless self.class.policy

    scope = self.class.scope.new(current_user, self.class.model)
    record = scope.resolve.find_by(id: id)

    return unless record

    raise GraphQL::ExecutionError, I18n.t('pundit.no_permission') unless self.class.policy.new(current_user, record).download?

  end

    'client_document_listing' => 'client_document_download',

    'deal_document_listing' => 'deal_document_download',
    'goal_document_listing' => 'goal_document_download',
    'group_document_listing' => 'group_document_download',

    'kpi_document_listing' => 'kpi_document_download',
    'password_document_listing' => 'password_document_download',
    'product_document_listing' => 'product_document_download',
    'user_document_listing' => 'user_document_download',
    'user_identifier_action_document_listing' => 'user_identifier_action_document_download',
    'variable_document_listing' => 'variable_document_download'

      listing_action = Action.find_by(key: listing_key)
      download_action = Action.find_by(key: download_key)

          user_id: listing_permission.user_id,
          action: download_action,
          role_id: nil
        )
      end
    end
  end

  def down
    # Permissions will remain - no rollback needed
  end
end

      cache: new InMemoryCache(),
      defaultOptions: {

          }
        }
