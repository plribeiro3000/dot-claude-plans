=== Reading ===

The gate went: added (default false) -> default flipped to true -> every existing company
backfilled to true -> the column removed entirely. SessionsController#create and
SessionsController (failure branch) call `SecurityEvent.create(...)` with no company-flag
check anywhere in the controller (see SPIKE.md Finding 2 for the full excerpt). The capture
is therefore unconditional for every company today, but the earliest possible row is bounded
by table creation: 2026-05-28 (migration 20260528120001_create_security_events.rb). Any
acceptance/signature event that happened before that date has no corresponding login-audit
row in security_events, regardless of which company it belongs to.
