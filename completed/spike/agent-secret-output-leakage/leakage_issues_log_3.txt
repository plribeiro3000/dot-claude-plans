=== ISSUE #44868 (OPEN as of research date) ===
URL: https://github.com/anthropics/claude-code/issues/44868
Title: "Claude Code exposes secrets from .env / .dev.vars files via grep -n and Read tool,
        despite CLAUDE.md prohibitions"
Labels: area:security, area:tools, enhancement, platform:windows

Real-world reproduction documented in the issue:
  - User asked Claude Code to help populate a .dev.vars file with API tokens
  - User accidentally pasted a malformed value
  - Claude Code ran `grep -n curl .dev.vars` to diagnose
  - grep returned the full matching line containing a real API token
  - Token was written to chat history before safety detection triggered
  - Token had to be rotated immediately

Root cause analysis in the issue:
  1. Safety checks run too late — fires on output already produced, not pre-execution
  2. Commands echo full content — grep, cat, head return entire lines including secrets
  3. CLAUDE.md is advisory only — instructions don't block tool execution

Proposed solutions in the issue:
  1. Path-based pre-execution filter (block commands targeting .env*, *.pem, *.key files)
  2. Output-side scrubber (redact high-entropy strings before appending to conversation)
  3. Structured secret file annotations
  4. "The model should not be trusted to police its own tool calls against secrets. The harness should enforce it."

Status: OPEN, unresolved

=== ISSUE #29434 (CLOSED: NOT PLANNED) ===
URL: https://github.com/anthropics/claude-code/issues/29434
Title: "[FEATURE] Mechanism to redact secrets/PII from the context window"

Key observation: "The context window in Claude Code is append-only and permanent. Once sensitive
data enters the context — whether inbound (a tool result echoes a secret) or outbound (a model
response summarizing that data) — it remains in every subsequent API call for the lifetime of
the session."

Proposed three options (Option 3 recommended by issue author):
  Option 1: First-party Anthropic server sanitizes prompts/tool responses
  Option 2: Third-party hooks for plugins to intercept and sanitize
  Option 3: Hybrid — default first-party + exposed hooks for customization

Status: CLOSED AS NOT PLANNED + stale label (no implementation, no Anthropic response)
