### Task 5 — Draft Phase 2 — Categorization and Proposal section
- **Objective:** Write the Phase 2 prompt section covering memory analysis and proposal generation.
- **What to write into the skill prompt:**
  - **Step 2.1 — Analyze each memory:** For each memory file, read the content and determine a recommended destination:
    - Use heuristics: keyword matching (e.g., "git push" → Git Push Safety), path matching (e.g., mentions `~/.claude/docs/` → Tier 2 doc), temporal (e.g., "resolved", "done" → drop), reference matching (e.g., mentions an existing plan → active work)

  - **Step 2.2 — Render proposal table:** Format the proposal for human review:
    - One row per memory with: source path, summary (first line or 1-sentence excerpt), recommended destination, rule fired, "why" explanation
    - If ≤~10 rows, render in-chat as markdown table
    - If >10 rows, write to `/tmp/cleanup-memories_proposal_<YYYYMMDD_HHMMSS>.md` and open with `open` per Output Formatting policy
  - **Output format:** Clearly scannable proposal; engineer can review all decisions at once before proceeding
- **Affected files:** Section in `~/.claude/commands/cleanup-memories.md`
- **Completion criteria:** Proposal table is human-readable; heuristics are explicit (engineer reading the prompt understands why each memory was categorized that way)

### Task 6 — Draft Phase 3 — Decision Collection section
- **Objective:** Write the Phase 3 prompt section covering engineer interaction and decision capture.
- **What to write into the skill prompt:**

  - **Step 3.2 — Collect per-row decisions:** Prompt for decisions on each row:

    - Explicit confirmation: "Ready to proceed? Type 'go' to apply all decisions, or 'abort' to exit."
  - **Output format:** Interactive, scannable, allows bulk shortcuts to reduce decision fatigue
- **Affected files:** Section in `~/.claude/commands/cleanup-memories.md`

### Task 8 — Draft Phase 4 — Apply Actions section (Part B: Per-Repo PR Workflow)
- **Objective:** Write the Phase 4 prompt section covering how PRs are created for each affected repo.
- **What to write into the skill prompt:**
  - **Step 4.3 — Prepare per-repo slices:** Group all file edits and additions by repo:
    - For each repo, gather all memories destined for `<repo>/CLAUDE.md`, runbooks, ADRs, etc.
    - For `~/.claude/` repo changes (CLAUDE.md global, Tier 2 docs), treat `.claude` as a special repo
  - **Step 4.4 — Create feature branch:** For each repo slice:
    - Validate preconditions: repo is on `develop`, tree is clean (no uncommitted changes, no staged files)
    - If preconditions fail, ask engineer to stash/commit and abort the cleanup
    - Check out `develop`, pull latest
    - Create feature branch: `feature/cleanup-memories-<YYYYMMDD>`
  - **Step 4.5 — Apply edits:** Apply all file edits to the repo in this branch (append to files, create new runbooks, etc.; use the edits prepared in Step 4.1-4.2)
  - **Step 4.6 — Commit and push:**
    - Stage only the files edited (do not add everything)
    - Commit with message: `chore(cleanup): add <N> memory items from cleanup-<YYYYMMDD>` (Angular conventions, no AI co-authorship)
    - Push with explicit refspec: `git push origin <branch-name>:refs/heads/<branch-name>` (per Git Push Safety in CLAUDE.md)
    - After push, set upstream tracking: `git branch --set-upstream-to=origin/<branch-name> <branch-name>`
  - **Step 4.7 — Open PR:** Use gh cli to open PR:
    - Title: Brief summary (e.g., "Clean up 3 memory items: Git rules, test conventions, ADR template")
    - Body: Bullet list of what was added/changed for this repo
  - **Output:** List of PRs created (repo, branch name, PR URL) for engineer review
- **Affected files:** Section in `~/.claude/commands/cleanup-memories.md`
- **Completion criteria:** PR workflow is clear; explicit refspec is mandatory; engineer understands PRs are opened but not merged

### Task 10 — Draft Phase 4 — Apply Actions section (Part D: Drop and Delete)
- **Objective:** Write the Phase 4 prompt section covering how "drop" decisions are finalized and memories are deleted.
- **What to write into the skill prompt:**
  - **Step 4.9 — Finalize drop decisions:** For memories marked "drop":
    - Confirm engineer decision (already collected in Phase 3)
    - No file edits, no commits, no PRs — just deletion
  - **Step 4.10 — Delete memories conditionally:** For each processed memory (edited, migrated, or dropped):
    - Delete the memory file from `~/.claude/projects/<encoded>/memory/` **only if its action succeeded**
    - For file edits: delete only after the commit is pushed and PR is open (verify via gh pr list or similar)
    - For plan migrations: delete only after the file is written and verified
    - For drops: delete immediately (no preconditions)
    - **Important:** If any action fails (file write permission denied, PR open failed), leave the memory in place and note the error in the report
  - **Output:** Count of memories deleted; list any that failed (leaving them in inbox for retry)
- **Affected files:** Section in `~/.claude/commands/cleanup-memories.md`
- **Completion criteria:** Delete logic is clear; memories are NOT deleted if their action fails; errors are captured for reporting
