KEY QUOTES (verbatim):

Origin: "The Law of Demeter (LoD), also called the principle of least knowledge, is a software design guideline..."
Authors: Ian Holland and Karl Lieberherr, 1987, Northeastern University, The Demeter Project

Core rules as stated on page:
"Each unit should possess only limited knowledge about other closely related units"
"Each unit should only communicate with its friends; avoid talking to strangers"
"Only interact with your immediate friends"

The "one dot" formulation:
"use only one dot" - code like a.m().n() violates the law, a.m() complies

Dog/legs analogy (from page):
"when one wants a dog to walk, one does not command the dog's legs to walk directly; instead, one commands the dog which then commands its own legs."

RELEVANCE TO to_h ANTI-PATTERN:
When a caller does `Thing.new(...).to_h`, then accesses `[:value]` and `[:type]` on the resulting hash, the caller is reaching INTO the object's internal representation (the hash structure) rather than calling methods on the object itself. While this is a single object chain, the deeper violation is that the caller must know the internal key structure of the hash — it breaks encapsulation. The LoD is not directly violated (it's one dot), but the encapsulation principle underneath LoD is violated: the caller knows and depends on the internal structure of what to_h returns.

PROBLEM: "You have an array in which certain elements mean different things."
SOLUTION: "Replace the array with an object that has a field for each element."

Fowler's example:
Before: row[0] = "Liverpool"; row[1] = "15";
After: row.setName("Liverpool"); row.setWins("15");

This is directly from Martin Fowler's Refactoring catalog (first edition, 1999, p. 163).

PRIMITIVE OBSESSION (Fowler & Beck, Refactoring, 1999):
"Most programming environments are built on a widely used set of primitive types: integers, floating point numbers, and strings."
"programmers are curiously reluctant to create their own fundamental types which are useful for their domain—such as money, coordinates, or ranges."
"Strings are particularly common petri dishes for this kind of odor: A telephone number is more than just a collection of characters."

Refactoring techniques recommended:
- Replace Primitive with Object
- Replace Array with Object
- Replace Type Code with Subclasses + Replace Conditional with Polymorphism
- Extract Class, Introduce Parameter Object
