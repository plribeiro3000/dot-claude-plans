################################################################################
# SUMMARY OF THE DELTA
################################################################################
The in-repo roles/4shark.mongodb is behind the dedicated ansible-role-mongodb on
every axis:

1. Version default: in-repo pins `mongodb_version: "4.0"` (roles/4shark.mongodb/defaults/main.yml:4).
   MongoDB 4.0 reached end of life in April 2022. The dedicated repo removed the
   default entirely and asserts the caller declares it.
2. Ubuntu codename: in-repo HARDCODES `bionic` (18.04) in the apt repo path.
   The dedicated repo templates it via `mongodb_ubuntu_codename` (default focal).
3. Package holds: in-repo has none. The dedicated repo holds all nine mongodb-org
   packages via dpkg_selections, which is what stops an `apt-get upgrade` from
   restarting mongod out of order and costing the replica set its quorum.
4. THP hardening: in-repo copies a legacy /etc/rc.local. The dedicated repo installs
   a proper systemd unit (disable-thp.service).
5. Service management: in-repo uses the old `service:` module; the dedicated repo uses
   `systemd:` with daemon_reload.
6. Hygiene: the dedicated repo has .ansible-lint, .yamllint, README, CHANGELOG,
   VERSION, meta/, renovate.json. The in-repo copy has none of these.

NOTE: roles/4shark.mongodb8 (defaults/main.yml:5 `mongodb_version: "8.2"`,
defaults/main.yml:8 `mongodb_ubuntu_codename: "noble"`) is a THIRD, separate copy of
the same capability living in the same repo — the 8.x-series sibling of 4shark.mongodb.
So the MongoDB provisioning capability currently exists in three places:
  - ansible/roles/4shark.mongodb   (stale, 4.0, bionic)
  - ansible/roles/4shark.mongodb8  (8.2, noble — used by provision-4client-mongodb-server.yml)
  - ansible-role-mongodb           (dedicated repo, versioned, consumed by the mongodb golden-AMI build)
