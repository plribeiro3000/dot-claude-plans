===== F) PIPECAT FUNCTION CALLING [URL G confirmed] =====

"Function calling (tool use) operates within Pipecat's pipeline structure."

Pipecat provides:
- Automatic schema derivation from function signatures
- Context aggregation and conversation history management
- Tool conversion to provider-native formats
- Pipeline integration plumbing

Developers must build:
- Function handlers (the actual logic)
- External API/service calls
- Error handling within handlers

"The documentation doesn't explicitly mention Anthropic Claude or MCP (Model Context
Protocol) servers. It discusses function calling generically across LLM providers."

Pipecat tool pattern (from fetched docs):
async def get_current_weather(params: FunctionCallParams, location: str, format: str):
    weather_data = {"conditions": "sunny", "temperature": "75"}
    await params.result_callback(weather_data)

context = LLMContext(tools=[get_current_weather])

→ Each MCP tool (e.g. mcp__postgres__query) must be re-implemented as a Pipecat
  FunctionCallParams handler that internally calls the postgres MCP server as a
  subprocess. The Claude Agent SDK's native MCP wiring does NOT carry over.

===== H) PIPECAT vs LIVEKIT COMPARISON [URL M confirmed] =====

"Pipecat: Every step—voice activity detection, streaming transcription, LLM call, speech
synthesis—is code you write and control."

"LiveKit: Your agent joins a WebRTC 'room' as a participant, subscribes to audio tracks,
and responds to events like 'new transcription received.'"

"Pipecat: Transport-agnostic. You choose the transport: Daily's WebRTC, Twilio Media
Streams, a raw WebSocket server, or local audio capture. The pipeline logic stays the
same regardless."

"LiveKit: Tightly coupled to WebRTC. You're coupled to LiveKit's WebRTC infrastructure."

===== M) MEDIARCORDER / PUSH-TO-TALK COMPLEXITY [WebSearch confirmed] =====

Browser push-to-talk minimal implementation:
1. navigator.mediaDevices.getUserMedia({ audio: true }) → MediaStream
2. MediaRecorder(stream) → starts recording on button press, stops on release
3. ondataavailable → audioChunks.push(chunk)
4. ondataavailable/stop → Blob → fetch('/api/stt', { body: blob })
5. STT API returns text → feed to existing text agent pipeline → display response

Mic waveform during recording (for visual feedback):
AnalyserNode from Web Audio API:
analyser.fftSize = 256
Uint8Array(analyser.frequencyBinCount)  // 128 data points
requestAnimationFrame loop → analyser.getByteFrequencyData(data)
→ draw bars from data array

This is approximately 30–50 lines of vanilla JS, no external libraries required.
Web Audio API FFT visualization during MediaRecorder capture is a standard,
browser-native pattern. No backend changes needed for this visualization.

CONFIRMED: mic waveform during recording is trivial Web Audio FFT — no framework
dependency.
