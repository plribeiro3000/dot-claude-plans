None of the sampled (or grepped) hook "command" values are prefixed with a
literal "bash " verb -- Claude Code invokes the path directly, which means
execution depends on the file's own shebang line + executable bit, not on a
hardcoded interpreter name in settings.json. Changing a script's shebang line
from #!/bin/bash to #!/bin/zsh would be picked up by the hook runner without
a settings.json edit -- ASSUMING settings.json invocation is the only call
path (see permissions.allow finding below, which is NOT shebang-driven).

--- permissions.allow entries tied to the literal "bash" verb ---

grep -c 'Bash(bash ~/.claude' ~/.claude/settings.json -> 33 entries

These are permission-matcher allow-list rules of the shape
`Bash(bash ~/.claude/scripts/<name>.sh:*)` or similar. Per CLAUDE.md's own
documented Command Safety Policy, the permissions matcher does a STRING-PREFIX
match against the literal command text typed by the agent (e.g. "bash
~/.claude/scripts/ruby.sh ..."). If a script's invocation verb changed from
"bash <path>" to "zsh <path>" (or to a bare "<path>" relying on the shebang),
every one of these 33 allow-list entries would need a matching rewrite, or
the agent would hit a manual permission prompt on every previously-silent
invocation.
