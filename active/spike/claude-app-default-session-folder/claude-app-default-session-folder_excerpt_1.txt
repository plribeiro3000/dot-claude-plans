Significance: this is a real, byte-verified persistence mechanism, but it is scoped to a DIFFERENT session-creation surface than the plain sidebar "+ New session"/Cmd+N flow the spike question is about. It fires inside a composer embedded in a claude.ai "Space" (Project) page -- the error-tag string `space_ccd_composer` appears earlier in the same function (not separately offset-cited). Behavior: if the Space has exactly ONE attached folder (`1===e.folders.length`), that folder is used automatically, every time, with no picker (`x(e.folders[0].path,s)`). If the Space has MULTIPLE folders, the composer checks `e.ccdFolderPath` -- a value persisted on the Space object itself via `updateSpace(e.id,{ccdFolderPath:s})` the first time the engineer picks a folder -- and reuses it silently on every subsequent session start from that same Space's composer, without re-prompting. If no `ccdFolderPath` is set yet and the Space has multiple folders, the placeholder reads "Choose on start" and a picker opens on first use.

This does NOT answer the spike's Sub-question 1 in the affirmative for the plain Cmd+N flow: it is a distinct, Space-scoped composer, and this spike found no evidence connecting it to the sidebar's ordinary "+ New session" button. It IS evidence that the underlying product has, elsewhere, already built a "remember my folder choice for next time" pattern -- just not exposed as a general per-app or per-workspace-root default in the surface the question is about.
