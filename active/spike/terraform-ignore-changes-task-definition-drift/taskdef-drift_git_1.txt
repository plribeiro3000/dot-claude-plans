WHAT THIS RESOLVES
=============================================================================

The README says (README:7-9):

  "Container definitions are marked `ignore_changes` so that GitHub Actions can inject full
   environment variables when registering new task definition revisions without Terraform
   overwriting them on the next apply."

and (README:159-160):

  "`container_definitions` is ignored in `lifecycle` — changes to environment variables
   or secrets must go through the CI/CD pipeline (GitHub Actions), not Terraform."

Both describe the state created by 5f0a472 (2026-02-20) and REMOVED by 13d32a0 (2026-03-20).
The README has been stale for ~4 months. The code of record is the empty `lifecycle {}` at
modules/ecs_service/main.tf:64, and 13d32a0's message states the intent explicitly:
"Removed ignore_changes on container_definitions so Terraform has full ownership of task
definition content."

This is NOT a cosmetic doc bug. It inverts who owns the task definition CONTENT, which is
the premise of any reasoning about what a `terraform plan` on this module means.
