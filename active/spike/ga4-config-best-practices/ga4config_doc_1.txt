TITLE: Understanding PII in Google's contracts and policies
=============================================================

What Google Considers PII:
"could be used on its own to directly identify, contact, or precisely locate an individual"

- Email addresses

- Phone numbers

- Pseudonymous cookie IDs
- Pseudonymous advertising IDs
- IP addresses
- Other pseudonymous end user identifiers

SOURCE 4: https://developers.google.com/analytics/devguides/collection/ga4/user-id
TITLE: Send user IDs — Google for Developers
=============================================================

Implementation:
"add the user_id parameter to the config command on each page of your website"
"To set or update the user_id after the initial page load, use the gtag('set') command."

Three states:
- Never signed in: Don't send the parameter
- Currently signed in: Send their user ID
- Previously signed in, now signed out: Send null (not empty string or "null" text)

"Don't set custom dimensions based on user IDs...too many unique values causes issues with Google Analytics data"

user_id is "a reserved system parameter used specifically to identify authenticated users" and must only be configured as a configuration parameter, never as a custom dimension or event parameter.

SOURCE 11: https://support.google.com/analytics/answer/9216061
TITLE: Enhanced measurement events
=============================================================

1. page_view: "each time the page loads or the browser history state is changed"
2. scroll: "the bottom of each page (i.e., when a 90% vertical depth becomes visible)"
3. click (outbound): "each time a user clicks a link that leads away from the current domain and to another website"
4. view_search_results: "each time a user is presented with a search results page, as indicated by the presence of a URL query parameter"
5. video_start, video_progress, video_complete: YouTube embeds at start, 10/25/50/75% progress, completion
6. file_download: "when a user clicks a link leading to a file" (PDF, Word, Excel, etc.)
7. form_start, form_submit: "first user interaction with a form" and "upon form submission"

Note: "no personally identifiable information is collected" must be ensured before enabling.
