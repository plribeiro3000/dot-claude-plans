title: "Cannot ignore changes for replication_specs when autoscaling is enabled"
state: closed

Body (via WebFetch summary):
The user wants fine-grained control over which fields in replication_specs
trigger Terraform updates when autoscaling is enabled — specifically wanting
to ignore changes to instance_size while still tracking other fields.

Quoted from the issue: "Block type 'replication_specs' is represented by a
set of objects, and set elements do not have addressable keys."

Terraform's lifecycle.ignore_changes cannot target individual nested
attributes within a set block — only entire top-level blocks can be ignored.
This traces to a Terraform core limitation (referenced in the issue:
hashicorp/terraform#26359), not something the mongodbatlas provider can work
around on its own within the ignore_changes mechanism.

=== NOTES ON #888 ===
- Confirms why a granular `lifecycle.ignore_changes = [replication_specs[0]...instance_size]`
  approach does not work for mongodbatlas_advanced_cluster — replication_specs
  is a set-typed block, and Terraform's ignore_changes cannot address
  individual attributes inside a set element. Only the whole replication_specs
  block (or nothing) can be ignored via this mechanism, which would also
  freeze disk size and node counts along with instance size.
