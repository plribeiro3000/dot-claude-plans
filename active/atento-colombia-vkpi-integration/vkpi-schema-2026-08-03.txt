================================================================================
READING NOTES
================================================================================

1. This dump is authoritative for STRUCTURE only.

2. The column set here differs from the files Atento sent:
     database              16 columns, NR_INDICADOR, NR_NUMERADOR, NR_DENOMINADOR
     Maqueta.csv (30-jul)  22 columns, NR_ID, RESULTADO, HC, HC_Total, DT_CREACION / DT_ACTUALIZACION
     Propuesta (02-ago)    22 columns, NR_ID, RESULTADO, HC, HC_Total, DT_CREATED / DT_MODIFIED
   The indicator column is NR_INDICADOR here and NR_ID in both files. What that
   divergence means — a structure not yet applied here, or a different
   environment — is not settled by this dump.

3. tb_dim_indicadores has NO column holding a 4Shark variable key. Its
   identifying columns are NR_ID (int) plus three name columns:
   NM_INDICADOR_STANDARD, NM_UTILIZADO_EN_EL_PAIS, NM_INDICADOR_EN_EL_PAIS.
   NM_INDICADOR_STANDARD is a cross-country standard name and is the only
   candidate for a stable textual key.

4. Every column in all four tables is nullable and none has a default. This is
   the same finding recorded as point 7 of the 28-jul document, still true.

5. DT_DATA is typed `date` in the database. The day/month inversion reported in
   point 6 of the 28-jul document is a load-process defect, not a type problem.

6. tb_dim_mapa_operacional_mensal holds the VKPI hierarchy — supervisor,
   gestor, gerente, superintendente, diretor and vice-presidente, each as an RE
   number plus a name. This is the parallel hierarchy that guardrail G1 forbids
   consuming; the platform's hierarchy of record is Simplex.
