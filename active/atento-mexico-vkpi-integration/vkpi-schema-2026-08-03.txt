================================================================================
READING NOTES
================================================================================

1. STRUCTURE SHAPE. The table is the equivalent of Colombia's
   `tb_dim_indicadores_score` and nothing else. Colombia's catalogue
   (`tb_dim_indicadores`) has no counterpart here, so an `Indicador` value
   resolves to nothing — there is no place holding the indicator's name,
   calculation, or any attribute.

2. THE PRIMARY KEY IDENTIFIES A ROW, NOT A MEASUREMENT. `PK_tbl_agentkpis_incentivos`
   covers `idAgent` alone, and that column is a surrogate identity —
   `COLUMNPROPERTY(OBJECT_ID('dbo.tbl_agentkpis_incentivos'), 'idAgent', 'IsIdentity')`
   returns 1. So the key is a row counter: it makes every row distinct while
   guaranteeing nothing about period + person + service + indicator, which is
   the combination the integration reads. This is Colombia's original defect,
   where the proposed key repeated on 98% of its values.

   The upside of the same fact: the table CAN hold one row per indicator per
   period per person. Nothing in its shape prevents that; what is missing is
   the constraint that would make it true.

3. `idAgent` IS NOT A PERSON IDENTIFIER, DESPITE THE NAME. It is the identity
   sequence from note 2 — a trap for whoever writes the load, because the name
   reads as the agent's code. The person candidates are `SAP`, `PBX` and
   `UserID`. Colombia settled this by confirming `NR_RE` is the Simplex code
   the platform already receives; Mexico needs the same confirmation, naming
   which one of the three it is.

4. THE DATE IS A STRING. `Fecha` is `nvarchar(10)`, so its format is a
   convention rather than a type — the ambiguity Colombia closed by delivering
   `yyyymmdd`. `Fecha_Actualizacion` is a real `datetime` defaulting to
   `getdate()`, which sets it at insert; whether it moves on update depends on
   their load process. There is no creation date.

5. THE VALUE IS SPLIT IN TWO. `Numerador` and `Denominador` are the shape
   Colombia had before collapsing them into a single `RESULTADO`. The question
   4Shark asked Colombia on 28-jul — which value represents the person's
   performance — applies here unanswered.

6. TWO SERVICE-SHAPED DIMENSIONS. `Servicio` and `Campaña` are both present,
   where Colombia has one (`NR_SERVIVIO_CODIGO`). Whether a variable is per
   indicator, per indicator+service, or per indicator+service+campaign is a
   definition that must exist before the platform identity can be satisfied.
